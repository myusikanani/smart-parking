4.6 Constraints and Assumptions

  • Internet dependency: Verification of dynamic QR tokens is performed against the cloud database and requires continuous network connectivity.
  • Browser camera access: Video streams require a modern browser and explicit user media permission (HTTPS or localhost).
  • Simulated hardware / test-mode payment: The physical boom barrier is simulated through software triggers and Razorpay transactions operate in test mode.
  • Clock synchronization assumption: The client smartphone clock and server clock differ by no more than ±15 minutes (handled by ±30 token steps drift window).
  • Operational scope assumption: The facility operates as a centralized multi-floor parking lot managed by a unified administrative team.

CHAPTER 8: SYSTEM IMPLEMENTATION

8.1 Dynamic QR Cryptographic Algorithm

To prevent pass duplication via screenshots, passes rotate every 30 seconds:

Token Format: PS-DYN|<bookingId>|<timeStep>|<hmacSignature>
• timeStep = Math.floor(currentTime / 30000)
• hmacSignature = HMAC_SHA256(bookingId + ':' + timeStep, SECRET_KEY)
• Backend validates current timeStep ± 30 steps (±15 minutes) for device clock drift tolerance.
